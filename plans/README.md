## Dependency notes

- **001 and 002 float to the top**: both restore trust in imported data (001 stops the current
  year's Economia from being silently dropped; 002 stops partial writes on a mid-import crash).
  Neither depends on anything; do them first.
- **004 depends on 002** — the importer changes in 004 add more per-row writes; they must land
  on top of the atomic-transaction wrapper, not before it.
- **011 depends on 010** — never split a 3,800-line money module without a characterization-test
  net under it first. 010 is the prerequisite plan for 011.
- **019 (invoice entity) depends on 004** — first-class faturas need the importer to already
  carry owner splits and the credit payment method.
- **021 (real-time sync) depends on 001 + 002** — a background two-way sync must read the sheet
  correctly (001) and write atomically (002) before it can run unattended.
- Plans 005, 006, 007, 008, 009, 012, 013, 014, 015, 016, 017, 018 are independent of each other.

## Findings considered and rejected (do not re-audit)

- **`saldoHeatmap.ts` thresholds**: correct — absolute R$ bands match the spreadsheet's
  conditional formatting (critical −500, tight 1000, ok 2000). No change.
- **Performance formula in `forecast/mod.rs`**: correct — subtracts Economia and projected
  remaining Diário, and `savings_rate_bps` uses registered Economia. No change.
- **`classify()` routing credit expenses to FixedOut**: by design (the fatura folds into a
  Saída lump at the due date — ADR-0001). Not a bug.
- **First month of an imported year has no prior-year carry-over seed**: structural; the seed
  comes from the live balance column, not a cross-year formula. Not a bug.
- **Dormant granular category tree in the schema**: intentional — demoted to free tags
  (migrations 20240612000003/04). Schema presence is harmless.
- **Client secret present in the packaged bundle**: expected for an installed/desktop OAuth
  client using PKCE — the secret is not confidential in that flow. Informational only.
